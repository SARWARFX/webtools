OPTIC STREAM // WEBRTC HARDWARE CAPTURE & MEDIA STREAM ARCHITECTURE

Technical specifications of W3C Media Capture and Streams, getUserMedia constraints, and camera hardware benchmarking.

The MediaDevices.getUserMedia Protocol

Modern browsers interact with physical webcam sensors through the W3C navigator.mediaDevices.getUserMedia() API. This grants web applications access to video and audio streams:

  • Strict User Permissions: Webcams cannot be accessed without explicit user opt-in prompt. Permissions are bound to HTTPS origins.
  • Resolution Constraints: Camera sensors can be probed using flexible constraints (ideal: 1920, exact: 1080) or allowed to default to native optical capabilities.
  • Hardware Acceleration: Stream frames are decoded directly via GPU video engines, rendering directly onto HTML5 <video> elements with near-zero latency.

Client-Side Snapshot Serialization

Capturing snapshots uses an off-screen HTML5 Canvas pipeline:

  • Pixel Blit: CanvasRenderingContext2D.drawImage() samples the active video buffer instantaneously.
  • Lossless Blob: canvas.toBlob() compiles pixels into uncompressed PNG binaries directly in RAM.
  • No Server Transfer: Frames never leave the browser sandbox.

Airgap Zero-Log Privacy Architecture

The Optic Stream camera test operates 100% locally. No video stream buffers, captured photos, or biometric records are ever transmitted over external networks or saved to persistent cookies.
