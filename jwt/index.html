Token Anatomy & Safe Unicode Decoding

A JSON Web Token consists of three base64url-encoded parts delimited by periods: header.payload.signature.

  • Header: Identifies the cryptographic algorithm (e.g. HS256, RS256) and token format type (JWT).
  • Payload: Contains public and private claims such as subject (sub), issuer (iss), and expiration timestamp (exp).
  • Signature: Digital digest ensuring the token payload has not been modified in transit.

SubtleCrypto In-Memory HMAC Verification

Conventional web JWT debuggers transmit private auth tokens and symmetric secret keys to cloud backends for validation. CyberTools performs signature verification entirely within your browser using the native window.crypto.subtle Web Crypto API.

The input secret key is imported into non-extractable CryptoKey buffers, and the signature bytes are tested against header.payload bytes with zero network latency and zero credential leakage.

Frequently Asked Questions

Is it safe to paste production API tokens?

Yes. CyberTools has zero backend servers. All token parsing, claim extraction, and signature checking takes place strictly within local browser memory.

Which signature algorithms can be verified?

Symmetric HMAC algorithms (HS256, HS384, HS512) are fully supported via the Web Crypto API. Asymmetric tokens (RS256, ES256) decode payload claims with full fidelity.

How does the expiration timer calculate relative deltas?

The engine compares the standard numeric Unix timestamp exp claim against the local system clock every second, providing precise live countdowns.

How are multi-byte Unicode strings handled?

Base64URL decoding utilizes URI component escape sequences, ensuring names, emojis, and non-ASCII character sets render without encoding corruptions.
