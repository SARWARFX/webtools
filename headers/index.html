The Core Defense Perimeter

HTTP response headers allow server operators to enforce strict security boundaries directly in the visitor's browser sandbox. Even if application code contains latent vulnerabilities, properly synthesized security headers block unauthorized script execution, isolate credentials, and prevent malicious iframing.

  • Content-Security-Policy (CSP): Restricts sources of executable scripts, stylesheets, images, and network connections, stopping Reflected and Stored XSS attacks.
  • Strict-Transport-Security (HSTS): Mandates HTTPS communication, eliminating SSL-stripping and man-in-the-middle attacks on public networks.
  • X-Frame-Options: Prevents third-party websites from rendering your site within an invisible iframe, neutralizing UI redressing and Clickjacking.
  • X-Content-Type-Options: Disables MIME sniffing, forcing browsers to respect the declared Content-Type and preventing polyglot script execution.

Permissions & Cross-Origin Isolation

Modern browser security standards extend far beyond basic transport encryption. The Permissions-Policy allows sites to permanently revoke browser hardware APIs (such as microphones, webcams, and payment processors) for all third-party embedded widgets.

Furthermore, Cross-Origin-Opener-Policy (COOP) isolates your top-level browsing context into an independent execution process, mitigating Spectre side-channel attacks and enabling high-resolution JavaScript performance timers.

Frequently Asked Questions

Why does my website break when using strict CSP?

Modern frontend frameworks often inject dynamic inline styles or evaluate templates at runtime. If your CSP lacks 'unsafe-inline' or appropriate cryptographic hashes/nonces, the browser will refuse to execute those resources.

What is HSTS Preloading?

Preloading registers your domain into an immutable list baked directly into Chrome, Firefox, Safari, and Edge source code. Browsers will never attempt an insecure HTTP connection, even on the very first visit.

Where do I paste these headers in Cloudflare Pages?

Save the generated Cloudflare snippet into a plain text file named _headers placed directly in the root output folder of your static build directory.
