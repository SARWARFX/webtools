1. Evaluation Order & Precedence

        

          Under the formalized IETF standard (RFC 9309), crawlers parse user-agent blocks by first identifying the most specific matching User-agent identifier. If no specific agent block matches the crawler's identity, the generic wildcard block (User-agent: *) is evaluated. Within a block:
        

        
    
          
  • The longest matching path rule takes precedence over shorter rules.
    • 
          
  • If an Allow and a Disallow rule match the exact same character length, Allow takes precedence.
    • 
          
  • Wildcards (*) match zero or more characters; the dollar symbol ($) denotes strict end-of-URL termination.
    •
